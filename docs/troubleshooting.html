Troubleshooting

Symptoms, causes, and fixes. If none of these match, please open an issue with the exact command line and (redacted) output.

zreview docs prints listening at… but the browser can't connect

Cause. The server binds to loopback by default (127.0.0.1). If you're running zreview docs inside a container, remote VM, or SSH session, your browser is on a different host and can't reach loopback.

Fix. Bind to a routable address and add the reachable host to the allowlist:

ZREVIEW_DOCS_ALLOWED_HOSTS=devbox.local,10.0.0.7 \
  zreview docs --addr 0.0.0.0:7777

If a firewall between your machine and the docs host is dropping traffic, no allowlist change will help — open the port on the firewall first.

403 forbidden host when hitting the docs server

Cause. The Host: header on the request is not on the allowlist. This is intentional — it defends against DNS rebinding (see T4).

Fix. Add the exact Host: value your browser sends (usually the hostname, sometimes with a port) to ZREVIEW_DOCS_ALLOWED_HOSTS:

ZREVIEW_DOCS_ALLOWED_HOSTS=devbox.local,devbox.local:7777 \
  zreview docs --addr 0.0.0.0:7777

Loopback names (localhost, 127.0.0.1, [::1]) are always accepted — you never need to list them.

CI complains about no provider API key

Cause. zreview review could not resolve any LLM provider credential. Nothing in the env, no AWS credential chain reachable.

Fix. Set exactly one of these in the job:

ProviderVariable
AnthropicANTHROPIC_API_KEY
OpenAIOPENAI_API_KEY
AWS BedrockStandard AWS credential chain: AWS_ACCESS_KEY_ID + AWS_SECRET_ACCESS_KEY, or an IAM role attached to the runner.

Then run zreview doctor in your CI pipeline before zreview review so misconfigurations fail fast. See CLI reference § doctor.

Index build is slow or expensive

Cause. By default zreview index uses the same LLM/embedding model as review. Review-grade models are overkill for chunk embeddings.

Fix. Point indexing at a cheaper embedding model separately from the review model. Configure the indexing model via ZREVIEW_INDEX_MODEL in your .zreview.yaml or environment — see Configuration. On very large repos, also prefer incremental over full rebuilds: run zreview index without --full so only changed files are re-embedded.

Review comment lands on the wrong line

Cause. The LLM produced a line number that didn't match any hunk in the diff. Line-snapping tried to relocate the comment to the nearest changed line and either landed off-by-one or too far away to snap safely.

Fix. This is a bug on our side, not a config problem. Please file it with:

  • the diff (git diff --unified=3 <from>..<to>),
  • the produced comment (from --format json),
  • the session .jsonl if available — it captures the pre-snap position and helps us reproduce.

Redact source content if it's sensitive; the diff structure alone is often enough.

Overlap section is empty

Cause. zreview overlap could not enumerate open PRs. Most often: GITHUB_TOKEN is unset, or the token lacks pull-request read scope on the repo.

Fix.

  • Confirm GITHUB_TOKEN is exported in the shell / job.
  • For fine-grained tokens, ensure Pull requests: Read is granted for the target repo.
  • For classic PATs, repo scope is sufficient. For public repos, public_repo.
  • Re-run with -vv to see the exact GitHub API error.

If the prefilter yields no candidates that is a legitimate empty result — there really are no overlapping PRs. That is different from “the overlap step didn't run”: the latter prints a diagnostic to stderr.

Org rules not injected

Cause. Either the rules repo is not configured, unreachable, or the YAML doesn't parse.

Fix.

  1. Confirm ZREVIEW_ORG_RULES_REPO is set: echo $ZREVIEW_ORG_RULES_REPO.
  2. Run zreview rules sync. This fetches the repo and prints load errors up-front.
  3. Run zreview rules list. Every rule expected to apply must appear here. If it doesn't:
    • Check enabled: true on the rule file.
    • Check repos: matches the current repo's owner/name.
    • For scope: path, verify at least one paths glob matches a changed file.
  4. See Review rules § How selection works for the full precedence.

Test coverage on internal/llm is 40%

Not a bug. After the OCR provider trim, internal/llm is smaller than the original upstream code but a lot of retained provider glue is only exercised end-to-end — not by unit tests yet. Coverage rises as Phase 6+ wires the retained providers into the review path. Track progress on the roadmap.

How to file a bug

For everything except security issues:

  • Open a ticket at github.com/shubam-disseqt/z-code-reviewer/issues.
  • Include: zreview version --json output, the exact command, and the first ~50 lines of stderr with -vv.
  • Redact any real diff content that isn't necessary to reproduce.

For security-relevant issues (credential leak paths, path traversal, RCE), do not use public Issues. See Security and the repo's SECURITY.md for private disclosure.
