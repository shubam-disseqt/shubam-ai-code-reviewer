GitHub Action

Drop the shubam-disseqt/shubam-ai-code-reviewer action into a workflow to run sacr review on every pull request. Composite action — runs the published Docker image against the checked-out workspace.

Minimal workflow

# .github/workflows/review.yml
name: AI review
on:
  pull_request:
    types: [opened, synchronize, reopened]

permissions:
  contents: read
  pull-requests: write

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0        # required so the PR base ref is available

      - uses: shubam-disseqt/shubam-ai-code-reviewer@v1
        with:
          pr-number: ${{ github.event.pull_request.number }}
          api-key: ${{ secrets.OPENAI_API_KEY }}
          github-token: ${{ secrets.GITHUB_TOKEN }}

That's it. Three lines of with: and every PR gets an inline review.

Required permissions

The workflow's permissions: block controls what the built-in GITHUB_TOKEN can do. For the default format: github path:

permissions:
  contents: read           # read the repo
  pull-requests: write     # post the review as inline comments
  security-events: write   # optional: upload SARIF to Code Scanning

Cross-PR overlap reads via pull-requests: read, which write subsumes. security-events: write is only needed when you opt into SARIF upload — see SARIF output.

Secrets

One secret in the minimal case: the LLM provider's API key, passed as api-key. The action routes it to the right env var for the chosen provider:

openaiOPENAI_API_KEY
anthropicANTHROPIC_API_KEY
deepseekDEEPSEEK_API_KEY
bedrockAWS_BEARER_TOKEN_BEDROCK

Pinning in production

- uses: shubam-disseqt/shubam-ai-code-reviewer@v1
  with:
    pr-number: ${{ github.event.pull_request.number }}
    image: ghcr.io/shubam-disseqt/sacr:v1.0.0
    api-key: ${{ secrets.OPENAI_API_KEY }}
    github-token: ${{ secrets.GITHUB_TOKEN }}

Pinning the image plus a version tag on the action (or a full commit SHA) is the safe combination for compliance-sensitive repos. Renovate and Dependabot understand both forms.

Common patterns

Switch provider

with:
  provider: anthropic
  model: claude-sonnet-4-6
  api-key: ${{ secrets.ANTHROPIC_API_KEY }}

Persist the index across runs

The container's home is ephemeral, so by default every job re-summarizes the PR's changed files (a few cheap-tier calls). To carry the index between runs, cache a directory under the workspace and point db-url at it. The container runs as uid 1000, so the cached directory must be writable by it. Add .sacr-cache/ to the repo's .gitignore.

- uses: actions/cache@v4
  with:
    path: .sacr-cache
    key: sacr-index-${{ github.repository }}
- run: mkdir -p .sacr-cache && chmod a+rwX .sacr-cache
- uses: shubam-disseqt/shubam-ai-code-reviewer@v1
  with:
    pr-number: ${{ github.event.pull_request.number }}
    api-key: ${{ secrets.OPENAI_API_KEY }}
    github-token: ${{ secrets.GITHUB_TOKEN }}
    db-url: sqlite:////workspace/.sacr-cache/index.db

Code Scanning

Set SACR_UPLOAD_SARIF=1 in the step's env: to upload scanner findings (gitleaks / semgrep / govulncheck) to GitHub Code Scanning in the same run. Scanner-sourced comments route to SARIF only; LLM comments still land inline. See SARIF output.

Block merge on critical findings

Review exit code 3 means “completed, found a CRITICAL finding.” Mark the review job as a required status check and merges are blocked until it clears.

Cost-limit runs

Skip AI review on trivial changes (docs, generated files) by gating the whole job on a paths filter:

on:
  pull_request:
    paths-ignore:
      - '**/*.md'
      - '**/docs/**'
      - '**/*.gen.go'
Forked PRs. secrets.* are not available on pull_request runs from forks, and the token is read-only. Use pull_request_target only if you understand the privilege-escalation risk (never checkout untrusted refs on that trigger), or gate the job on github.event.pull_request.head.repo.full_name == github.repository.

When it doesn't post comments

The two most common causes:

  1. Missing pull-requests: write. The action ran, produced findings, and got 403 from the GitHub API. Check the job's permissions: block.
  2. Fork PR. Forked PRs get a read-only token. The action will still run, still emit comments to the job log, but the API call to post them fails. Use format: stdout for fork PRs or accept the limitation.
