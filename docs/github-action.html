GitHub Action

Drop the shubam-disseqt/z-code-reviewer action into a workflow to run zreview review on every pull request. Composite action — installs the CLI and calls it in the same job.

Minimal workflow

# .github/workflows/review.yml
name: AI review
on:
  pull_request:
    types: [opened, synchronize, reopened]

permissions:
  contents: read
  pull-requests: write

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0        # required so the PR base ref is available

      - uses: shubam-disseqt/z-code-reviewer@v0
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}

That's it for the default path: pull request event, Anthropic provider, comments posted inline on the PR. Everything else is a knob.

Inputs

All inputs are optional. Sensible defaults keep the minimal workflow above one env var wide.

InputPurposeDefault
version zreview version to install. Empty means latest release. latest
provider anthropic | openai | bedrock | deepseek | openai-responses anthropic
model Model name, e.g. claude-sonnet-4-6. provider default
from Base ref for the diff. PR base ref (GITHUB_BASE_REF)
to Head ref for the diff. PR head ref (GITHUB_HEAD_REF)
format stdout | json | github. github
db-url ZREVIEW_DB_URL passthrough for a persistent index. none (JIT mode)
rules-repo ZREVIEW_ORG_RULES_REPO passthrough — owner/repo[@ref]. none
extra-args Additional flags spliced into the zreview review call. —

Required permissions

The workflow's permissions: block controls what the built-in GITHUB_TOKEN can do. For the default format: github path:

permissions:
  contents: read           # read the repo
  pull-requests: write     # post the review as inline comments

If you also want the cross-PR overlap surface, that already reads via pull-requests: read, which write subsumes. Nothing extra to add.

Forked PRs. By default, GitHub gives fork PRs a read-only token — the action cannot post comments. Configure workflow_run or pull_request_target patterns carefully if you need reviews on fork PRs, and read the preventing pwn-requests guide first. Do not blindly copy pull_request_target patterns.

Secrets

The action needs exactly one secret in the minimal case: the LLM provider's API key. Set it under Settings → Secrets and variables → Actions.

ProviderSecret
anthropicANTHROPIC_API_KEY
openaiOPENAI_API_KEY
openai-responsesOPENAI_RESPONSES_API_KEY
deepseekDEEPSEEK_API_KEY
bedrockAWS credential env: AWS_ROLE_ARN via OIDC, or AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY.

Pinning versions

Composite actions pin best by SHA. If you need reproducible reviews across PRs, replace the tag with a commit SHA:

- uses: shubam-disseqt/z-code-reviewer@<40-char-sha>
  with:
    version: v0.1.0             # pin the CLI too

Renovate and Dependabot both understand this form and will PR updates on release.

Common patterns

Shared index database

Point every reviewer at the same Postgres so summaries are computed once. Populate the DB from a scheduled indexer job, not from the review workflow itself.

- uses: shubam-disseqt/z-code-reviewer@v0
  with:
    db-url: ${{ secrets.ZREVIEW_DB_URL }}
  env:
    ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}

Org rules from a separate repo

- uses: shubam-disseqt/z-code-reviewer@v0
  with:
    rules-repo: disseqt/z-review-rules@main
  env:
    ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
    ZREVIEW_ORG_RULES_TOKEN: ${{ secrets.RULES_REPO_READ_TOKEN }}

Block merge on blocker findings

Review exit code 3 means “completed, found a blocker.” Wire that to a required check:

- uses: shubam-disseqt/z-code-reviewer@v0
  env:
    ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
# The step fails (exit 3) if any comment has severity: blocker.
# Mark this job as a required status check to block merges.

Cost-limit runs

Skip AI review on trivial changes (docs, generated files) by gating the whole job on a paths filter:

on:
  pull_request:
    paths-ignore:
      - '**/*.md'
      - '**/docs/**'
      - '**/*.gen.go'

When it doesn't post comments

The two most common causes:

  1. Missing pull-requests: write. The action ran, produced findings, and got 403 from the GitHub API. Check the job's permissions: block.
  2. Fork PR. Forked PRs get a read-only token. The action will still run, still emit comments to the job log, but the API call to post them fails. Use format: stdout for fork PRs or accept the limitation.
