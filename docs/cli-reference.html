CLI reference

Every subcommand, every flag, every exit code. Order matches roughly the order you'll reach for them.

Not every command is wired yet. Only sacr version and sacr docs ship end-to-end today. Every other subcommand below is documented against its target UX — the flag names and exit codes are locked, the implementations land in later phases. See the phase tag next to each heading and ROADMAP.md.

Global flags

Available on every subcommand.

FlagMeaning
-v, --verboseVerbose logs to stderr. Repeat (-vv) for debug-level tool traces.
-h, --helpPrint usage for the subcommand and exit 0.
--versionPrint the version string and exit 0. Equivalent to sacr version.

sacr version shipped

Prints the build identity. Machine-readable with --json.

FlagMeaning
--jsonEmit a JSON object instead of the human line.

Output shape

$ sacr version
sacr 0.2.0 (commit deadbeef, go1.23.4, darwin/arm64)

$ sacr version --json
{
  "version":   "0.2.0",
  "commit":    "deadbeef",
  "goVersion": "go1.23.4",
  "os":        "darwin",
  "arch":      "arm64"
}

Exit codes

Always 0. If sacr version is failing, the binary itself is broken.

sacr docs shipped

Serves this documentation on a local loopback HTTP server. Content is embedded in the binary; no network calls.

FlagMeaningDefault
--addrTCP address to bind. Use 127.0.0.1:0 to pick a free port. Non-loopback binds require the host allowlist below.127.0.0.1:0
--openauto: open the browser only when a TTY is attached and $CI is unset. always: always try. never: never try.auto

Environment

VariableMeaning
SACR_DOCS_ALLOWED_HOSTSComma-separated list of Host: header values the server will accept in addition to localhost, 127.0.0.1, and [::1]. Required when --addr binds a non-loopback interface.

Security posture

  • Loopback-only by default. Non-loopback binds require an explicit SACR_DOCS_ALLOWED_HOSTS entry — guards against DNS rebinding (T4 in Architecture § Threats).
  • All responses ship a strict CSP: default-src 'self'; script-src 'none'; frame-ancestors 'none'.
  • No third-party fonts, scripts, or images. Every asset is under the embedded FS.

Exit codes

CodeMeaning
0Server started, shut down cleanly on SIGINT.
1Bind failed or an unexpected runtime error occurred.

sacr review Phase 8

The main event. Runs the review pipeline over a diff and emits comments in the chosen format.

Phase 8 deliverable. Flag names below are the target UX and are considered stable. Implementation lands in Phase 8 — see ROADMAP.md.

Diff selection (pick one)

FlagMeaning
--from <ref> --to <ref>Review the diff from..to. Typical PR usage: --from origin/main --to HEAD.
--commit <sha>Review a single commit (equivalent to --from <sha>^ --to <sha>).
--pr <number>Fetch the PR from the current repo's origin and review it. Requires GITHUB_TOKEN.

Output

FlagMeaning
--format <fmt>stdout (default): human-readable. json: one JSON array of comments. github: post inline review comments back to the PR (requires --pr and GITHUB_TOKEN).
--output <path>Write to a file instead of stdout. Only meaningful with --format stdout or --format json.
--resume <session-id>Resume from a prior session JSONL file. Re-runs failed sub-agents; keeps successful comments. See Architecture § Pipeline.

Exit codes

CodeMeaning
0Review completed. No blocker-severity findings.
1General runtime error (network, LLM provider, git).
2Configuration error (bad flags, missing API key, invalid YAML). See Configuration.
3Review completed but produced one or more blocker-severity findings. Wire this to CI to gate merges.

sacr index Phase 4

Builds or refreshes the persistent code index used by sacr review and sacr overlap. Without an index, review falls back to just-in-time context loading via the agent's file_read / code_search tools — smaller signal, higher token cost per run.

FlagMeaning
--repo <path>Path to the git checkout to index. Defaults to CWD.
--fullForce a full re-index. Otherwise the incremental walker only touches files changed since the last run.
--db <dsn>Database DSN. Overrides $SACR_DB_URL. Accepts postgres://... or sqlite:///path/to/file.db.
Cost note. Indexing calls an embedding model per chunk. Point it at a cheap model (e.g., a small embedding endpoint) separately from your review model — SACR_INDEX_MODEL controls that. See Configuration.

sacr rules Phase 7

Inspect and refresh the org-level rules pulled from $SACR_ORG_RULES_REPO.

SubcommandMeaning
sacr rules listList every loaded rule with id, scope, severity, and whether it would apply to the current repo/path.
sacr rules syncFetch the latest rules commit from $SACR_ORG_RULES_REPO (respecting $SACR_ORG_RULES_REF). Idempotent.

See Review rules for the YAML schema and authoring guide.

sacr overlap Phase 5

Reports which currently-open pull requests overlap in scope or risk merge conflicts with the target PR. Runs the deterministic prefilter (Jaccard on title, symbol/file intersection) before spending any LLM budget on a batched verdict pass.

FlagMeaning
--pr <number>PR to compare all other open PRs against.

Requires GITHUB_TOKEN with read access to pull requests. Output is a human-readable table by default; --format json for machine consumption. If the LLM batch call fails, the prefilter results are still printed — overlap never blocks review.

sacr doctor Phase 9

Pre-flight checks. Run this in CI before sacr review so misconfigurations fail fast with a readable message.

Checks performed:

  • git binary on $PATH and version ≥ 2.30.
  • Repository is a git checkout and has fetched the requested refs.
  • An LLM provider credential is present: ANTHROPIC_API_KEY, OPENAI_API_KEY, or a resolvable AWS credential chain for Bedrock.
  • The index database (SACR_DB_URL, or the per-repo default under ~/.sacr/index/) opens and answers a ping.
  • SACR_ORG_RULES_REPO (if set) is reachable and the YAML parses.
  • GITHUB_TOKEN (if --format github is intended) has PR read+write scope.

Exit codes

CodeMeaning
0All checks passed.
2One or more configuration problems found. Details printed to stderr.

Exit-code summary

Uniform across the CLI so CI wiring is simple.

CodeMeaning
0Success.
1General runtime error (network, provider, git, IO).
2Configuration error — bad flags, missing credentials, unreachable dependency.
3sacr review only: review completed with at least one blocker-severity finding.
